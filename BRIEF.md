# BRIEF: csqtt-win, Windows-порт csqtt 2.5.0

## Цель
Нативный Windows-клиент csqtt с полным набором функций Android-версии. Ядро берём из апстрима с минимальными патчами, чтобы обновления апстрима и сообщества подтягивались обычным `git merge`.

## Архитектура (решено)
- **Репозиторий** — форк `amurcanov/csqtt` с сохранённой историей; `upstream` подключён как remote. Android-часть (`app/`) не трогаем: это эталон поведения и дизайна.
- **Ядро** — `rust-client` апстрима. Патчи только изолированные, под `cfg(windows)`: Wintun вместо TUN fd (`tun.rs`), `run_tun` в `dispatcher.rs`, errno, watchdog родителя (`main.rs`). Все отличия от апстрима перечислены в `WINDOWS-PATCHES.md`.
- **Хост** — Rust, каталог `windows/` (workspace):
  - `csqtt-svc` — Windows-служба (SYSTEM). Запускает ядро дочерним процессом по тому же stdio-протоколу, что Android `TunnelManager`. Отвечает за Wintun, IP/MTU/DNS, маршруты, защиту от петли, recovery-политики, настройки, секреты (DPAPI).
  - `csqtt` — CLI и трей без UAC. Общается со службой через named pipe с ACL.
  - WebView2-окна: капча, ручная капча, VK-авторизация.
- **Дизайн GUI** — 1:1 с Android (Compose/Material 3). GUI делаем отдельным этапом после CLI+трей, стек выберем тогда.

## Сценарии
1. Пользователь ставит csqtt-win установщиком, импортирует конфиг (ссылка или файл в формате Android) и нажимает «Подключить» в трее, горячей клавишей или командой `csqtt connect`. Весь трафик идёт через туннель.
2. VK запрашивает капчу: открывается окно WebView2, пользователь решает её, туннель продолжает подниматься.
3. Пользователь добавляет `game.exe` в исключения: его трафик идёт мимо туннеля, остальной — через туннель.
4. Пользователь разворачивает сервер на VPS по SSH из клиента (как Deploy в Android).
5. Сеть меняется (смена Wi-Fi, сон и пробуждение): туннель восстанавливается сам. UI закрыли — туннель живёт в службе.

## Критерии готовности
- [ ] Ядро с патчами собирается под `x86_64-pc-windows-msvc`. `cargo test` апстрима проходит на Windows, кроме Unix-only тестов.
- [ ] `csqtt connect` на реальном сервере и VK: внешний IP равен IP сервера, DNS работает, утечек мимо туннеля нет (IPv4, IPv6, DNS).
- [ ] `csqtt disconnect`, а также падение службы или ядра не оставляют сломанных маршрутов. Служба при старте чистит хвосты.
- [ ] Скорость и задержка не хуже ~80% Android-клиента в той же сети и на том же сервере.
- [ ] Все режимы ядра работают: ручной и auto VK, капча и ручная капча через WebView2, все транспорты и обфускации, воркеры, маршрутизация по доменам и IP, белые списки, исключение RU-зон, TURN-подсети.
- [ ] Исключения по приложениям: выбранный exe выходит в сеть со своим реальным IP.
- [ ] Recovery: смена сети, сон и пробуждение, потеря TUN — туннель поднимается без участия пользователя.
- [ ] Трей: индикатор состояния, вкл/выкл, глобальная горячая клавиша, живые логи (`csqtt logs -f`).
- [ ] Импорт и экспорт настроек совместимы с Android (ссылка/QR-формат, файл).
- [ ] Деплой, обновление и удаление сервера по SSH, хранение host key и SSH-ключей.
- [ ] Проверка обновлений через релизы форка.
- [ ] Установщик ставит службу и Wintun и чисто удаляется. Есть portable zip.
- [ ] Логика `*Policy.kt` перенесена в Rust вместе с тестами (портированы Kotlin unit-тесты).
- [ ] Merge нового коммита апстрима занимает минуты: проверка — тестовый merge.

## Вне объёма этой версии
- Android-специфичное: виджет, Quick Tile, TV-режим, оптимизация батареи.
- Автозапуск с Windows и автопауза по Wi-Fi (не выбраны; добавить их несложно).
- ARM64, Linux.
- UWP/Store-приложения в per-app исключениях (как у Mozilla VPN и других).
- Коммерческое распространение: запрещено лицензией PolyForm Noncommercial. Лицензию и авторство сохраняем.

## Ограничения
- Rust 1.97.1, edition 2024, MSVC toolchain. Windows 10 1809+ / 11, x64.
- Wintun (подписанный драйвер WireGuard), WebView2 Runtime.
- Для тестов есть свой сервер и VK.
- Проект: `D:\Политех\Программы\csqtt-win`. Работаем в VS Code.

## Допущения
- Протокол stdio ядра (`CAPTCHA_SOLVE|`, `VK_JS_BOOTSTRAP:` и т.д.) одинаков для Android и Windows, хост повторяет `TunnelManager.kt`.
- Защита от петли: маршруты `0/1` и `128/1` в Wintun, host-маршруты на TURN-IP и сервер через физический шлюз, плюс `IP_UNICAST_IF` для сокетов ядра (патч в одном месте создания сокетов).
- Per-app: ядро уже содержит netstack-smoltcp и `direct_relay`. Соединение исключённого процесса (порт → PID → exe через `GetExtendedTcp/UdpTable`) отправляем в direct-путь. Драйвер WFP не нужен.
- Формат настроек хранится в JSON, его поля совпадают с `SettingsStore.kt`.

## Открытые вопросы
- Стек GUI: Slint, egui, Tauri или Compose Desktop (последний переиспользует `app/ui/*.kt`). Решаем после CLI+трей, критерий — 60 fps при потоке логов.
- Подпись бинарников (SmartScreen).
