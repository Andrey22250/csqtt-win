# csqtt-win: Windows-порт csqtt

Windows-клиент csqtt 2.5.0 (форк [amurcanov/csqtt](https://github.com/amurcanov/csqtt)). Программа организует защищённый сетевой туннель поверх протоколов TURN/RTP с маскировкой трафика под звонки VK Calls.

Полное руководство пользователя с таблицами параметров и кодов ошибок доступно в файле [README-windows.md](README-windows.md).

---

## 1. Что это и из чего состоит

csqtt-win — клиент csqtt для Windows. Он состоит из трёх взаимодействующих компонентов:

- **`client.exe` (сетевое ядро)**: скомпилированное ядро `rust-client` с изолированными патчами под Windows. Работает с виртуальным сетевым адаптером Wintun, защищает собственные управляющие сокеты от зацикливания через `IP_UNICAST_IF` и контролируется родительской службой.
- **`csqtt-svc.exe` (системная служба)**: фоновая служба Windows (запуск под учетной записью `NT AUTHORITY\SYSTEM`). Управляет сетевым адаптером Wintun, назначением IP-адресов и DNS, таблицей маршрутизации (маршруты `0.0.0.0/1` и `128.0.0.0/1`), правилами защиты от утечек DNS (NRPT), хранением зашифрованных секретов (DPAPI) и автоматическим восстановлением сети после сбоев.
- **`csqtt.exe` (CLI и системный трей)**: консольная утилита управления и фоновый значок трея. Работает от имени обычного пользователя без повышения привилегий UAC и передает команды службе через защищенный именованный канал (Named Pipe).

Схема взаимодействия:
```text
csqtt.exe (CLI / трей) -> [Named Pipe \\.\pipe\csqtt-win] -> csqtt-svc.exe (SYSTEM) -> [stdio / Wintun] -> client.exe (ядро)
```

## 2. Требования

### Для сборки из исходников
- Операционная система: Windows 10 (версия 2004 / сборка 19041 или новее) или Windows 11 x64.
- Компилятор Rust 1.97+ с целевой платформой `x86_64-pc-windows-msvc` (edition 2024).
- Visual Studio Build Tools (компоненты C++ MSVC и Windows SDK) или Visual Studio Community 2022/2026.
- PowerShell 5.1 или PowerShell 7+.
- Опционально: Inno Setup 6 (компилятор `ISCC.exe`) для создания исполняемого инсталлятора `setup.exe`.

### Для работы приложения
- Microsoft Edge WebView2 Evergreen Runtime (необходим для работы окон решения капчи и авторизации VK; предустановлен в Windows 11 и актуальных сборках Windows 10).
- Права администратора: требуются исключительно для разовой установки, удаления или аварийной очистки службы (`csqtt-svc.exe install` / `uninstall` / `cleanup`), а также первого запуска службы (`sc.exe start csqtt-win`). Повседневное использование (`csqtt.exe` CLI и трей) выполняется **без прав администратора**.

## 3. Сборка из исходников

### Шаг 1. Загрузка драйвера Wintun
Перед первой сборкой запустите скрипт загрузки драйвера:
```powershell
powershell -NoProfile -File scripts\windows\fetch-wintun.ps1
```
Скрипт скачивает архив `wintun-0.14.1.zip` с официального сайта и извлекает `wintun.dll` (amd64) и файл лицензии в каталог `scripts\windows\cache\wintun\`.

> [!NOTE]
> Переменная `$WintunSha256` в скрипте `fetch-wintun.ps1` содержит пустой плейсхолдер. Скрипт выводит предупреждение и вычисленный хеш SHA256, после чего продолжает работу. При необходимости зафиксируйте хеш в скрипте.

### Шаг 2. Сборка и упаковка дистрибутива
Сборка всех компонентов и подготовка дистрибутива выполняются скриптом `package.ps1`:
```powershell
powershell -NoProfile -File scripts\windows\package.ps1
```

Дополнительные параметры:
- `-Version <строка>`: переопределить номер версии (по умолчанию считывается из `windows\csqtt-svc\Cargo.toml`);
- `-SkipBuild`: пропустить шаг компиляции через `cargo build` и упаковать уже скомпилированные бинарные файлы.

Скрипт выполняет:
1. Компиляцию сетевого ядра `rust-client` в режиме `--release`.
2. Компиляцию службы и CLI в каталоге `windows`: `cargo build --release -p csqtt-svc -p csqtt-cli`.
3. Формирование каталога релиза `dist\csqtt-win-<версия>-windows-x64\` со следующим составом:
   - `csqtt-svc.exe` — служба Windows;
   - `csqtt.exe` — консольный клиент и трей;
   - `client.exe` — исполняемый файл ядра;
   - `wintun.dll` и `wintun-LICENSE.txt` — сетевой драйвер;
   - `domains.txt` — списки доменов маршрутизации;
   - `README-windows.md` — руководство пользователя;
   - `LICENSE` — лицензия проекта.
4. Создание zip-архива `dist\csqtt-win-<версия>-windows-x64.zip` и файла контрольной суммы `.sha256`.
5. Если в системе обнаружен `ISCC.exe` (Inno Setup 6), скрипт автоматически компилирует инсталлятор `dist\csqtt-win-<версия>-setup.exe` на основе сценария `windows\installer\csqtt-win.iss`.

## 4. Развёртывание сервера (Deploy)

Сервер csqtt можно развернуть двумя способами:
1. **Из окна приложения**: вкладка «Деплой».
2. **Из консоли**: команда `csqtt deploy`.

### Подготовка бинарных файлов сервера
Для развертывания с Windows требуются скомпилированные Linux-бинарники сервера:
1. Скомпилируйте серверные бинарники с помощью `rust-server\build_linux.bat` (требуются `zig` и `cargo-zigbuild`).
2. Поместите файлы в каталог `server\` рядом с `csqtt.exe` (либо укажите другой каталог через флаг `--assets`):
   - `csqtt-linux-amd64` (для серверов x86_64 / amd64);
   - `csqtt-linux-arm64` (для серверов aarch64 / arm64);
   - `csqtt-linux-armv7` (для серверов armv7l / armv7);
   - `deploy.sh` (bash-скрипт установки на сервере).

### Команда развертывания (`csqtt deploy`)
```powershell
.\csqtt.exe deploy --host <IP_или_домен> [параметры...]
```

Поддерживаемые флаги:
- `--host <хост>`: IP-адрес или доменное имя VPS (обязательный параметр);
- `--port <порт>`: порт SSH на сервере (по умолчанию `22`);
- `--user <пользователь>`: имя пользователя SSH (по умолчанию `root`);
- `--key <путь>`: путь к приватному ключу SSH (OpenSSH или PEM);
- `--passphrase-env <переменная>`: имя переменной окружения с парольной фразой для ключа;
- `--sudo`: использовать повышение привилегий через `sudo`;
- `--docker`: развернуть сервер в Docker-контейнере вместо системной службы systemd;
- `--peer-port <порт>`: UDP-порт сетевого туннеля (по умолчанию `46000`);
- `--web-port <порт>`: HTTPS-порт веб-панели управления (по умолчанию `46002`);
- `--web-login <логин>`: имя администратора веб-панели (по умолчанию `admin`);
- `--secret-path <путь>`: секретный путь веб-панели (URL prefix);
- `--assets <каталог>`: каталог с файлами сервера (по умолчанию папка `server\` рядом с `csqtt.exe`).

### Переменные окружения для паролей
- `CSQTT_SSH_PASSWORD`: пароль SSH для подключения (если не задан и ключ `--key` не указан, пароль будет запрошен в консоли со стандартного ввода; ввод отображается);
- `CSQTT_MAIN_PASSWORD`: пароль подключения к туннелю (если не задан, генерируется случайный пароль из 16 символов);
- `CSQTT_WEB_PASSWORD`: пароль администратора веб-панели (если не задан, генерируется случайный пароль из 16 символов);
- `CSQTT_WEB_LOGIN`: логин веб-панели (если не указан через `--web-login`);
- `CSQTT_SUDO_PASSWORD`: пароль sudo (при использовании `--sudo`).

### Проверка ключей сервера (TOFU)
При первом подключении к новому серверу CLI выводит отпечаток ключа и запрашивает подтверждение: `Доверять этому ключу? [y/N]:`. Доверенные отпечатки сохраняются в файле `%LOCALAPPDATA%\csqtt-win\known_hosts.json`. Если ключ узла изменился, подключение немедленно прерывается с предупреждением о возможной атаке MITM.

### Синхронизация после успешной установки
После успешного развертывания CLI обращается к локальной службе `csqtt-win` через IPC и автоматически сохраняет адрес сервера, порты и сгенерированный пароль в активный профиль и защищенное хранилище секретов. Если служба не запущена, параметры выводятся в консоль для ручного ввода.

### Удаление сервера (`csqtt undeploy`)
```powershell
.\csqtt.exe undeploy --host <хост> [--port 22] [--user root] [--key <файл>] [--passphrase-env <переменная>] [--sudo] [--peer-port 46000] [--assets <каталог>]
```

## 5. Установка на Windows

### Вариант А. Установщик Setup
Запустите файл `csqtt-win-<версия>-setup.exe` от имени Администратора. Инсталлятор скопирует файлы в `%ProgramFiles%\csqtt-win`, зарегистрирует службу `csqtt-win`, запустит её через `sc.exe start csqtt-win` и по желанию добавит трей в автозагрузку. Каталог программы в `PATH` не добавляется: вызывайте `csqtt.exe` по полному пути или добавьте папку в `PATH` вручную.

### Вариант Б. Портативная установка (Portable ZIP)
1. Распакуйте архив в постоянную папку (например, `C:\Program Files\csqtt-win`).
2. Убедитесь, что файлы `csqtt-svc.exe`, `csqtt.exe`, `client.exe` и `wintun.dll` лежат в одной папке.
3. Дважды щёлкните `csqtt.exe` и в красной плашке нажмите «Установить и запустить службу», подтвердите запрос администратора. Это нужно один раз (и после переноса папки).

   То же из консоли администратора: `.\csqtt-svc.exe setup`.

**Когда работает служба.** Служба запускается вместе с приложением (окном или треем) и останавливается, когда закрыто и окно, и трей: при остановке туннель, маршруты и DNS-правило снимаются. С загрузкой Windows она сама не стартует. Права администратора нужны только для установки и удаления службы: запускать и останавливать её может обычный пользователь.

## 6. Использование

Все повседневные команды выполняются от обычного пользователя без прав администратора.

### Окно приложения

```cmd
csqtt gui
```

Открывает окно приложения (то же самое делает двойной клик по `csqtt.exe`): вкладки «Подключение», «Туннель», «Деплой», «Логи», «Маршрут» (исключения), «Инфо»; импорт и экспорт — кнопкой со стрелками в шапке. Окно можно открыть и из трея (пункт «Открыть окно»). Повторный запуск выводит уже открытое окно на передний план. Если служба не установлена или не запущена, вверху появится красная плашка с кнопкой «Установить и запустить службу»: она запросит права администратора и сама выполнит `csqtt-svc.exe setup`. Нужен WebView2 Runtime (в Windows 11 есть по умолчанию).

### Импорт конфигурации
Импорт профиля по ссылке:
```powershell
.\csqtt.exe import "csqtt://ey..."
```
Импорт из JSON-файла экспорта csqtt:
```powershell
.\csqtt.exe import backup.json
```

### Подключение и мониторинг
```powershell
# Подключение к туннелю
.\csqtt.exe connect

# Просмотр статуса, IP, DNS, числа воркеров и переданных байт
.\csqtt.exe status

# Отключение
.\csqtt.exe disconnect
```

### Просмотр журнала событий
```powershell
# Потоковый вывод логов в реальном времени
.\csqtt.exe logs -f

# Вывод последних 50 строк
.\csqtt.exe logs -n 50
```

### Системный трей и глобальная горячая клавиша
Запуск фонового значка в области уведомлений Windows:
```powershell
.\csqtt.exe tray
```
- Иконка в трее отображает статус соединения и всплывающие оповещения.
- Двойной клик левой кнопкой мыши переключает подключение/отключение.
- Правый клик открывает контекстное меню: «Подключить», «Отключить», «Войти в VK», «Показать логи», «Выход».
- Глобальная комбинация клавиш **`Ctrl + Alt + V`** переключает туннель из любого активного окна Windows.

### Капча и авторизация VK
- **Решение капчи**: фоновое решение выполняется через скрытый движок WebView2. При необходимости интерактивного ввода открывается графическое окно решения капчи.
- **Вход в VK через браузер**:
  ```powershell
  .\csqtt.exe vk-login
  ```
  Команда открывает окно браузера WebView2 для авторизации в VK, перехватывает токен доступа и сохраняет его в защищенное хранилище службы.
- **Сброс авторизации VK**:
  ```powershell
  .\csqtt.exe vk-logout
  ```

### Исключения приложений (Split Tunneling)
Трафик указанных приложений направляется напрямую через физический сетевой интерфейс (`direct_relay`) мимо виртуального адаптера Wintun. Определение процесса выполняется через сопоставление сетевых таблиц WinAPI (`GetExtendedTcpTable` / `GetExtendedUdpTable`).

```powershell
# Просмотр списка исключений
.\csqtt.exe apps list

# Добавление приложения в исключения
.\csqtt.exe apps add game.exe

# Удаление приложения из списка
.\csqtt.exe apps remove game.exe
```
*Изменения списка исключений вступают в силу при следующем подключении туннеля.*

### Настройки и секреты
```powershell
# Просмотр всех настроек активного профиля
.\csqtt.exe settings get

# Просмотр конкретного параметра
.\csqtt.exe settings get peer

# Изменение параметра
.\csqtt.exe settings set workers_per_hash 10

# Сохранение защищённого секрета в хранилище DPAPI службы
.\csqtt.exe secret set connection_password_encrypted "пароль"

# Экспорт конфигурации (формат совместим с другими клиентами csqtt)
.\csqtt.exe export out.json
.\csqtt.exe export --secrets out-with-secrets.json
```

### Проверка обновлений
```powershell
.\csqtt.exe update-check
```

## 7. Обновление и удаление

### Удаление программы
- **При установке через Setup**: удалите программу через системный раздел Windows «Параметры» -> «Приложения» -> «Установленные приложения» -> «csqtt-win» -> «Удалить».
- **При портативной установке**: в окне на вкладке «Инфо» нажмите «Удалить службу» (запросит права администратора), затем удалите папку программы и каталог данных `%ProgramData%\csqtt-win`.
  То же из PowerShell от имени **Администратора**:
  ```powershell
  cd "C:\Program Files\csqtt-win"
  .\csqtt-svc.exe uninstall
  .\csqtt-svc.exe cleanup
  ```
  После этого удалите каталог программы и каталог данных `%ProgramData%\csqtt-win`.

### Обновление из апстрима (для разработчиков)
Репозиторий оформлен как форк апстрима с подключенным remote `upstream`:
```powershell
git fetch upstream
git merge upstream/main
```
Все отличия и патчи ядра под Windows изолированы и описаны в файле [WINDOWS-PATCHES.md](../WINDOWS-PATCHES.md).

## 8. Хранение данных и диагностика

### Расположение данных
- Общесистемный каталог службы: **`%ProgramData%\csqtt-win\`** (`C:\ProgramData\csqtt-win\`):
  - `settings.json` — конфигурация приложения и профилей соединения;
  - `secrets.json` — защищенные секреты (пароли, токены VK), зашифрованные системным API Windows DPAPI (`CryptProtectData` с флагом `CRYPTPROTECT_LOCAL_MACHINE` и дополнительной энтропией `csqtt-win`);
  - `host_keys.json` — сохраненные отпечатки серверов;
  - `routes_journal.json` — журнал установленных сетевых маршрутов (используется для гарантированного отката при сбоях);
  - `logs\` — текстовые журналы работы службы.
- Пользовательский каталог: **`%LOCALAPPDATA%\csqtt-win\`**:
  - `known_hosts.json` — база доверенных ключей SSH для деплоя;
  - `webview2\` — изолированные кэш-каталоги браузерного движка.

### Диагностика
При возникновении проблем со связью после аварийного выключения ПК запустите консоль с правами Администратора и выполните:
```powershell
.\csqtt-svc.exe cleanup
```
Команда принудительно удаляет оставшиеся маршруты из журнала `routes_journal.json`, сбрасывает правила перехвата DNS (NRPT) и корректно освобождает интерфейс Wintun.

Подробная диагностика типичных неполадок и полная сводка параметров конфигурации приведены в [README-windows.md](README-windows.md).

## 9. Состояние проекта

### Проверено
- Сборка `rust-client` под `x86_64-pc-windows-msvc`: 369 тестов пройдено (с Windows-патчами), 10 пропущено (9 интеграционных e2e требуют тестового сервера в Linux/WSL, 1 нагрузочный soak-тест).
- Все крейты workspace `windows` компилируются без предупреждений; тесты: csqtt-logic 188, csqtt-svc 86, csqtt-cli 81, csqtt-deploy 89, csqtt-ipc 6 — все проходят.
- Модульные тесты pure-logic компонентов (политики, парсеры событий, хранилища настроек, деплой).
- Дымовое тестирование IPC через Named Pipe (`csqtt-ipc`).
- Дымовое тестирование окон WebView2.

### Ожидает проверки на живом стенде
- Реальное подключение через службу к живому серверу csqtt с поднятием Wintun-интерфейса и проверкой отсутствия утечек DNS/IPv6.
- Интерактивное решение капчи и авторизация через живой аккаунт VK в окне WebView2.
- Проверка раздельного туннелирования (Split Tunneling) для исключенных процессов на реальном сетевом трафике.
- Сборка и прогон инсталлятора на сборочной машине с Inno Setup 6 (`ISCC.exe`).
- Сквозное развертывание сервера на реальный VPS (`csqtt deploy`) со скомпилированными бинарниками `rust-server`.

### Известные плейсхолдеры
- `DEFAULT_REPO` в `windows\csqtt-deploy\src\update.rs`: содержит значение `"OWNER/csqtt-win"`, подлежащее замене на реальный адрес репозитория форка при публикации.
- Контрольная сумма `$WintunSha256` в `scripts\windows\fetch-wintun.ps1`: оставлена пустой, вычисляется динамически при загрузке архива.
